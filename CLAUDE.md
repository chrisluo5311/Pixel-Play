# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Pixel Play is a Claude Code **mod**: a plugin of function hooks (not a standalone app). It adds a `/music` command and a docked pane that shows an animated half-block pixel-art sprite and plays a playlist through `mpv` (+ `yt-dlp` for YouTube). The repo is both the plugin (`pixel-player`, `.claude-plugin/plugin.json`) and its own marketplace (`pixel-play`, `.claude-plugin/marketplace.json`, `source: "./"`).

There is no package.json, build step, or npm dependencies. The `claude-code` and `claude-code/testing` imports are provided by the Claude Code runtime; `tsconfig.json` extends `.claude-plugin/types/tsconfig.json`, which Claude Code lays down when the mod loads (gitignored).

## Commands

```sh
claude plugin validate .          # validate manifest/hooks
claude plugin test .              # runs every *.test.ts(x) under the dir (currently just player.test.ts); no per-test filter
claude --plugin-dir .             # run Claude Code with this checkout loaded; /reload-plugins hot-reloads
node scripts/png2sprite.mjs       # regenerate hooks/skins.gen.ts from assets/ (Node 18+, no deps)
```

Runtime requirements for actual playback: `brew install mpv yt-dlp`.

## Architecture

- `hooks/hooks.json` lists the module entry: `hooks/register.tsx`. It exports `register: Register`, which wires `session.start`, `command.run` (`/music` verbs), `ui.render` for the `Pane` with id `pixel-player`, and `session.end`.
- **State**: shared plugin state is declared as atoms in `register.tsx` (`player`, `playlist`, `skin`, `frame`, `volume`) and their types are the contract in `types/index.d.ts` (augments `PluginState['pixel-player']` in the `claude-code` module). If you add/rename an atom, update that declaration too. Persistent preferences (`skin`, `volume`, cached `titles`) go through `$.store` and are restored in `session.start`.
- **Playback** lives in module-level variables (`stream`, `generation`, `ticker`, `titles`). A hot reload drops the old module, so `session.start` resets `player` to `STOPPED`. Every `play()` bumps `generation`; async loops check `mine !== generation` to bail out when superseded — preserve this pattern when touching playback. A track exiting with code 0 auto-advances (wrapping).
- **mpv integration**: mpv is spawned via `$.process.spawn` with `--script=<plugin root>/mpv/progress.lua`. That Lua script writes `@@pos|<pos>|<dur>|<paused 0/1>|<title>` lines to stdout every second; `parseProgress` in `hooks/player.ts` parses the last such line. Changing one side means changing the other (and its test). mpv also gets `--input-ipc-server=$TMPDIR/pixel-play-<id>.sock` (one id per module load, short enough for macOS's 104-byte socket path limit); `mpvCommand` sends JSON IPC lines through `/usr/bin/nc -U` via `$.process.run`, since `$.process.spawn` gives no stdin or signals to a running child. Pause/resume use it, and `progress.lua` reports the `pause` property (immediately, via `observe_property`), so the `paused` status follows mpv. Binaries are found by checking `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` (no PATH lookup). Volume is still passed only at spawn, so it applies from the next track.
- **Playlist file** is `~/.claude/pixel-play/playlist.txt`, deliberately outside the plugin folder because an installed plugin's folder is replaced on update. A legacy `<plugin root>/playlist.txt` is migrated on first use. Format: one URL/path per line, `#` comments, optional ` # title` suffix (`parsePlaylist`).
- **Tests** run with no fs/process/clock: hook the engine events beneath the plugin (`on('fs.read', …)`, `on('process.spawn', async function* …)`, `mock.clock/store/env`). See the fake mpv in `player.test.ts`; a fake child should wait on `mock.clock` and `next.signal`, or `command.run`/stop never settles.
- `hooks/player.ts` holds pure helpers (parsing, IPC lines, time/progress-bar/equalizer formatting) — the easy place to add testable logic.
- **Sprites**: `hooks/pixel.tsx` renders a `Sprite` (palette + one char per pixel per frame, `.` = transparent) as `▀` half-blocks, cropping to the opaque bounding box across frames and downscaling to fit the pane width. `hooks/skins.gen.ts` is generated by `scripts/png2sprite.mjs`: each `assets/png/NN-name.png` (40×40) defines a skin, animated from `assets/frames/NN-name/<n>.png` when that folder exists, otherwise a single still frame — never edit it by hand. Tests assume 10 skins × 5 frames; update `player.test.ts` if that changes.
